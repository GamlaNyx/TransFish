# TransFish 设计说明

> 一块浮在桌面上的液态玻璃：按下快捷键，它出现；翻完一句话，它消失。

TransFish 是一个常驻 Windows 托盘的即时翻译小窗。它只做两件事：

1. **全局快捷键呼出**一个很小的翻译窗口；
2. **自动检测语种并翻译**，不要求用户先选语言。

本文记录这两个功能背后的产品取舍、交互细节与技术实现，作为 v0.1 的设计基线。

---

## 1. 产品定位

### 1.1 目标场景

| 场景 | 用户动作 | 期望 |
| --- | --- | --- |
| 读英文文档 / 论文 | 选中复制 → 按 `Ctrl+Alt+T` | 窗口带着剪贴板内容出现，译文已经在路上 |
| 回英文邮件 | 按快捷键 → 输入中文 → `Enter` | 立刻得到英文，`Enter` 再按一次即复制 |
| 看日文 / 韩文网页 | 复制 → 呼出 | 自动判断语种，译成中文 |
| 查一个词 | 呼出 → 输入 | 不打断当前窗口太久，`Esc` 就走 |

典型单次使用时长 3–10 秒，每天数十次。设计目标是**降低每次调用的仪式感**，而不是提供翻译工作台。

### 1.2 明确不做（v0.1）

- 不做历史记录、收藏、生词本；
- 不做多段落 / 文档翻译、PDF 翻译；
- 不做划词悬浮球、屏幕 OCR；
- 不做账号体系、云同步；
- 不内置离线模型。

这些能力都会把「纸条」变成「应用」，与定位冲突。未来若加入，应保持为可选扩展，不改变主流程。

### 1.3 成功标准

- 冷启动后，从按下快捷键到光标落在输入框 **< 150 ms**；
- 一次短句翻译的端到端时间主要取决于网络，应用自身开销 **< 80 ms**；
- 单次操作不超过「呼出 → 输入/粘贴 → Enter → Esc」四步；
- 用户不需要理解「源语言 / 目标语言」概念也能一直用对方向。

## 2. 交互设计

### 2.1 主流程

```
              ┌──────────────────────────────┐
   快捷键 ───▶ │  呼出窗口（置顶、聚焦）        │
              └──────────────┬───────────────┘
                             │ 剪贴板自上次呼出后有变化？
                 ┌───────────┴───────────┐
                 │ 是                    │ 否
                 ▼                       ▼
        预填剪贴板文本            聚焦空输入框
        （只填入，不自动发送）
                 │                       │
                 └───────────┬───────────┘
                             ▼
                  输入 / 粘贴 → Enter
                             ▼
                  自动检测语种 → 智能选方向
                             ▼
                     展示译文（可复制）
                             ▼
                  Esc / 失焦 → 隐藏窗口
```

### 2.2 窗口行为

- **无边框、透明、置顶、不占任务栏**：视觉上是一张浮在桌面上的纸片，不参与窗口管理。
- **位置**：首次出现时位于鼠标所在显示器的上方居中（工作区高度的 16% 处），并保证底部不超出工作区；多显示器时跟随鼠标，而不是固定主屏。
- **拖动与位置记忆**：标题栏（含左侧握把、品牌区、空白处）均可拖动窗口；移动停止 650 ms 后写入 `windowPosition`，下次呼出沿用。呼出时校验该位置仍落在某个显示器工作区内（至少露出 120×40），显示器拔插/分辨率变化导致位置失效时自动回退到顶部居中。托盘「回到顶部居中」可手动复位。
- **置顶开关**：标题栏图钉与托盘菜单都能切换 `alwaysOnTop`，即时作用于原生窗口并持久化；默认开启，让纸片不被其他窗口盖住。
- **高度自适应**：窗口高度 = 玻璃内容高度 + 24 px 阴影留白，随内容在 180–800 px 之间变化；设置页内容固定，独立滚动。
- **失焦收起**：切到其他窗口即隐藏（可关闭）。呼出后的 350 ms 内忽略失焦事件，避免 Windows 抢焦点导致的「一闪而过」；拖动窗口不会触发收起：左键按住且指针仍在窗内时忽略失焦，拖动结束后 1.2 秒内同样忽略，避免 Windows 在移动循环里短暂收回焦点导致小窗消失。
- **常驻托盘**：左键点托盘图标 = 呼出/收起；右键菜单提供打开、设置、窗口置顶、回到顶部居中、开机启动、退出。
- **单实例**：重复启动只会重新呼出已有窗口。

### 2.3 键盘

| 按键 | 行为 |
| --- | --- |
| `Enter` | 翻译；若译文已是最新且输入未变，则复制译文 |
| `Shift+Enter` | 换行 |
| `Ctrl+Enter` | 翻译（与 Enter 等价，但可在任意焦点触发） |
| `Esc` | 设置页 → 返回翻译页；翻译页 → 隐藏窗口 |
| `Ctrl+,` | 打开 / 关闭设置 |
| 全局 `Alt+T`（默认） | 呼出 / 收起窗口 |

> 选择 `Alt+T` 的原因是单手可按、不与系统快捷键冲突、且 T 与 Translate 关联。若被其他程序占用，启动时自动尝试 `Ctrl+Alt+T` → `Alt+Shift+T` → `Ctrl+Shift+T`，并在窗口内提示；用户也可在设置里录制新组合。

### 2.4 剪贴板策略

- 仅在**剪贴板内容相对上次呼出发生变化**时预填，避免每次呼出都重复同一段旧文本；
- 预填内容 trim 后为空或超过 5000 字时不予填入；
- **预填只写入输入框，不自动发起翻译**：剪贴板里可能临时存着密码、令牌、验证码，静默外发是不可接受的隐私风险。呼出后按 `Enter` 或点「翻译」才发送；
- 「粘贴后立刻翻译」只作用于用户主动在输入框内按 `Ctrl+V` 的行为，那是明确的发送意图；
- 复制译文后同步记忆该文本，避免下一次呼出把它当作「新剪贴板内容」再预填一遍。

### 2.5 状态与反馈

| 状态 | 界面 |
| --- | --- |
| 未配置密钥 | 系统填充引导面板：说明用途 + 「填写 AccessKey」 |
| 空闲（已配置） | 输入框 + 键位提示；品牌鱼形只出现一次，在标题栏 |
| 翻译中 | 顶部 2 px 强调色进度线 + 「正在翻译…」 |
| 成功 | 小号「译文」标签 + 17 px 系统字体译文 + 来源/目标语言与耗时 |
| 失败 | 系统红填充面板 + 可操作按钮（重试 / 打开设置 / 回到输入） |
| 快捷键冲突 | 顶部通知条 + 「更换」直达设置 |
| 保存成功 / 已复制 | 底部居中深色胶囊 toast，1.8 s 消失 |

## 3. 视觉设计

设计关键词：**液态玻璃、光、留白**。界面是一块浮在桌面上的 Regular 液态玻璃，内容直接落在材质上，而不是卡片套卡片。

### 3.1 材质与变体

- 全应用只有一层玻璃：`.slip`。标题、输入、结果、页脚都是这层材质上的内容；输入框、按钮、开关使用系统填充色，不再叠加玻璃。
- 采用 **Regular** 变体：适合承载文字与控件，在任意桌面背景下保持可读性。**Clear** 变体只在样式里预留（用于未来照片/视频背景的媒体场景），当前界面不使用，也不与 Regular 混用。
- 玻璃由四层合成：
  1. 背景层：呼出时用只读 GDI 抓取窗口所在区域的桌面缩略图（120 px 宽），在 Rust 内编码为 BMP data URL，经 IPC 交给前端；
  2. 模糊层：`filter: blur(50px) saturate(125%)`，把缩略图放大并虚化，得到真实的桌面色彩与明暗；
  3. 色调层：`--ambient`（同一区域的平均色）参与柔和径向渐变，叠白色线性渐变，保证文字对比度；
  4. 高光层：顶部斜向镜面高光 + 18 s 缓慢漂移，1 px 内缘高光与 0.5 px 外缘暗线定义玻璃边缘；低对比阴影只负责浮起感。
- 明暗随系统：`prefers-color-scheme` 切换色调层与文字 token；深色下背景图额外 `brightness(.82)`，避免亮桌面把深色玻璃冲淡。
- 降级：`prefers-reduced-transparency` 回退为不透明材质，`prefers-reduced-motion` 关闭高光漂移，`prefers-contrast: more` 加深边缘与文字。

### 3.2 色彩与文字

| Token | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `--label` | `#0b0b0c` | `#f5f5f7` | 主文字、图标 |
| `--label-2` | label 60% | label 62% | 次级文字、标签 |
| `--label-3` | label 40% | label 42% | 提示、禁用 |
| `--fill-1/2/3` | 118,118,128 @ 12/18/26% | 同色 @ 14/20/28% | 输入框、胶囊、hover |
| `--accent` | `#007aff` | `#0a84ff` | 主按钮、焦点、置顶态 |
| `--red` | `#d70015` | `#ff453a` | 错误 |

- 文字使用系统活力色（label / secondary / tertiary），不取背景平均色，保证任意背景下可读；
- 强调色只用于主按钮、焦点环、置顶态与链接式按钮；错误使用系统红；界面不出现第二种彩色；
- 字体：系统无衬线栈 `SF Pro Text → Segoe UI Variable Text → Microsoft YaHei UI`，中文与拉丁同族；不使用内置衬线字体；
- 字号：输入与译文 17 px，控件 14–15，标签 13，说明 12，脚注 11；正文不额外加字距。

### 3.3 版式与形状

- 窗口宽 480 px，玻璃圆角 26 px，四周留 12 px 透明阴影边；
- 内边距 18–20 px，区块间距 12–16 px，控件高 30–36 px，遵循 4 px 基准；
- 形状：玻璃 26、面板 18、输入 14、控件 10、胶囊 999；
- 结构：品牌头（方向胶囊、图钉、设置）→ 输入 → 结果/错误/引导 → 页脚；不使用硬分隔线，靠留白与层次区分；
- 页脚左侧快捷键或来源/耗时，右侧复制；主按钮为强调色胶囊，次按钮为系统填充。

### 3.4 图标与动效

- 图标按 SF Symbols 的比例重绘：1.6–1.8 px 圆头描边、24 网格、几何简洁；包括滑杆式设置、图钉、文稿复制、对勾、感叹号圆、左尖括号；品牌是单色鱼形 glyph，不再使用朱砂印章；
- 材质进入：180 ms 内透明度与模糊同时收敛（materialize），不用弹跳；
- 高光 18 s 缓慢漂移；hover 只改填充，按下 scale .97；reduced-motion 下退化为淡入。

### 3.5 桌面背景采样

- `window::summon` 在窗口显示前调用 `backdrop::capture_data_url` 与 `window::sample_ambient`，只读取屏幕像素，不修改任何窗口属性；
- 采样区域就是窗口将要出现的位置；不落盘、不上传，退出即丢弃；
- 拖动窗口后背景图保持呼出时的采样，直到下一次呼出。这是无边框透明窗在 Windows 上的取舍：不启用 DWM acrylic/blur（曾导致窗口几何异常与桌面黑屏），材质完全由 CSS 合成。

```
┌──────────────────────────── TransFish (Tauri 2) ────────────────────────────┐
│                                                                              │
│  WebView (React 19 + TS)                  Rust core                          │
│  ┌───────────────────────────┐            ┌──────────────────────────────┐   │
│  │ App.tsx                   │  invoke    │ lib.rs  commands / lifecycle │   │
│  │  ├ Translator.tsx         │ ─────────▶ │  ├ bootstrap / translate     │   │
│  │  ├ Settings.tsx           │            │  ├ save_settings             │   │
│  │  └ Icons / lang / api     │ ◀───────── │  ├ test_credentials          │   │
│  └───────────────────────────┘  events    │  └ copy_text / height / hide │   │
│                                            │                              │   │
│                                            │ window.rs  summon / place    │   │
│                                            │ tray.rs    tray / menu       │   │
│                                            │ settings.rs  persistence     │   │
│                                            │ volc.rs    signature + API   │   │
│                                            └──────────────┬───────────────┘   │
└───────────────────────────────────────────────────────────┼──────────────────┘
                                                            │ HTTPS
                                                ┌───────────▼────────────┐
                                                │ 火山引擎机器翻译 API     │
                                                │ translate.volcengineapi │
                                                └────────────────────────┘
```

### 4.1 技术选型

| 选择 | 理由 |
| --- | --- |
| Tauri 2 而非 Electron | 安装包 ~3 MB、常驻内存 ~30 MB；对「随手呼出」的工具，启动与内存是核心体验 |
| React + TypeScript + Vite | 组件状态清晰，HMR 迭代快；类型约束命令与事件载荷 |
| 原生 Rust 后端 | 签名、HTTP、窗口定位、全局快捷键都在主进程完成，前端不接触密钥 |
| 纯 CSS，无 UI 框架 | 视觉高度定制，避免为几个控件引入运行时 |
| 火山引擎机器翻译 | 官方文档齐全，支持自动检测语种；单接口即可覆盖需求 |

| `src-tauri/src/window.rs` | 呼出/收起、拖动位置记忆与有效性校验、按鼠标所在显示器定位、全局快捷键注册 |
| `src-tauri/src/tray.rs` | 托盘图标、菜单（含置顶与回到居中）、开机启动与退出 |
| `src-tauri/src/lib.rs` | 状态、命令（含置顶切换）、生命周期、失焦策略、单实例 |
| `src/App.tsx` | 会话状态、翻译序列控制、事件订阅、快捷键、窗口高度上报 |

### 4.3 命令与事件

命令（前端 → Rust）：

| 命令 | 说明 |
| --- | --- |
| `bootstrap` | 返回设置视图、版本、快捷键错误、通知、是否 dev |
| `translate(text, target?)` | 翻译一段文本；`target=null` 时按智能/固定模式决定 |
| `test_credentials(ak?, sk?)` | 用 `LangDetect` 验证密钥与网络，返回检测结果 |
| `save_settings(patch)` | 校验并保存；快捷键变更会试注册并回滚 |
| `set_always_on_top(enabled)` | 设置原生窗口置顶、持久化并刷新托盘勾选 |
| `copy_text(text)` | 写剪贴板并同步去重记忆 |
| `set_window_height(height)` | 高度钳制在 180–800，并保证不越出工作区 |
| `hide_window` | 隐藏主窗 |
| `ready` | 前端就绪后按需首次呼出（无密钥则打开设置） |

事件（Rust → 前端）：`summon { clipboard }`、`open-settings`、`settings-changed`、`toast`。

### 4.4 翻译流程与「智能方向」

1. 文本校验：trim、非空、≤ 5000 字符；
2. 目标语言：
   - 固定模式：使用设置中的目标语言；
   - 智能模式：先按字符猜测——含假名/谚文 → 中文；含汉字 → 英文；其余 → 中文；
3. 请求 `TranslateText` 时**不传 `SourceLanguage`**，让服务端自动检测，并在响应里取 `DetectedSourceLanguage`；
4. 若处于智能模式且检测结果与猜测方向矛盾（典型：只有汉字的日文被猜成「译英」），**再请求一次**正确方向，替换结果；
5. 返回译文、检测到的源语言、目标语言、耗时、RequestId。

这样用户永远不需要先选源语言；只有明确选择固定目标语言时才跳过纠偏。

### 4.5 火山引擎签名

请求签名采用 V4（HMAC-SHA256），关键约定：

- Host `translate.volcengineapi.com`，Region `cn-north-1`，Service `translate`，Version `2020-06-01`；
- 参与签名的头：`host`、`x-content-sha256`、`x-date`（不含 `content-type`、`content-length`、`user-agent`）；
- 规范请求：

```
POST
/
Action=TranslateText&Version=2020-06-01
host:translate.volcengineapi.com
x-content-sha256:<sha256(body)>
x-date:<YYYYMMDDTHHMMSSZ>

host;x-content-sha256;x-date
<sha256(body)>
```

- 待签字符串 `HMAC-SHA256\n<x-date>\n<date>/cn-north-1/translate/request\n<sha256(canonical_request)>`；
- 派生密钥链：`HMAC(secret, date) → region → service → "request"`；
- `Authorization: HMAC-SHA256 Credential=<AK>/<scope>, SignedHeaders=..., Signature=...`。

### 4.6 错误处理

后端把网络、HTTP、业务错误统一成 `{ code, message, retryable }`：

| code | 触发 | 前端表现 |
| --- | --- | --- |
| `no_credentials` | 未配置密钥 | 错误面板 + 「打开设置」 |
| `auth` | 401/403、AccessKey/签名类错误码 | 提示检查密钥 + 「打开设置」 |
| `rate_limited` | 429 / 限流错误码 | 「重试」 |
| `timeout` / `network` | 15 s 超时或连接失败 | 「重试」 |
| `bad_request` / `unsupported_pair` | 参数或语言对不支持 | 只展示说明 |
| `too_long` / `empty` | 本地校验 | 聚焦输入框 |
| `service_error` / `bad_response` | 5xx 或不可解析 | 「重试」 |

前端用递增序号丢弃过期响应，避免快速连按 Enter 时旧结果覆盖新结果。

### 4.7 数据与安全

- 设置文件：`%APPDATA%\com.transfish.app\settings.json`，原子写入（临时文件 + rename）；损坏文件重命名为 `settings.broken.json` 保留排查；
- AccessKey **只保存在本机**，不上传到任何第三方；界面只展示 `AKLT…9f2c` 形式的掩码；
- 密钥以明文 JSON 存储（v0.1 取舍）：首次使用可接受，后续可接入 Windows DPAPI 或凭据管理器；
- 请求仅发往 `https://translate.volcengineapi.com`，CSP 禁止外部脚本与任意连接；
- 无遥测、无崩溃上报。

## 5. 关键取舍

| 决策 | 备选 | 取舍理由 |
| --- | --- | --- |
| Tauri 2 | Electron | 体积/内存差一个数量级；工具类应用常驻成本必须低 |
| 一个窗口承载翻译与设置 | 独立设置窗口 | 保持「只有一个纸片」的心智模型，避免多窗口焦点问题 |
| 无边框透明窗 + 自绘阴影 | 系统标题栏 | 玻璃浮起感；系统标题栏会破坏材质的连续边缘 |
| 失焦即收起 | 常驻可见 | 呼出式工具的核心是「不占地方」；350 ms 宽限解决抢焦点 |
| 智能方向 + 检测纠偏 | 强制用户选方向 | 符合「自动检测语种」的需求；多一次请求只在必要时发生 |
| 快捷键冲突自动降级 | 直接报错 | 用户不该因为别的软件占用 Alt+T 就无法使用 |
| 自由拖动 + 位置记忆 | 固定顶部居中 | 常用位置因人而异；记住后不必每次找窗口，位置失效时自动回退居中 |
| 剪贴板只预填、不自动翻译 | 呼出即翻译 | 剪贴板常临时存着密码或令牌，静默外发的隐私风险大于省下一次 Enter |
| 系统无衬线 + SF 风格图标 | 内置衬线字体 / 第三方图标库 | 与液态玻璃和苹果规范一致，零字体体积，跟随系统字号与字形 |
| CSS 合成玻璃 + 桌面缩略图采样 | DWM acrylic / blur | 原生特效在透明 WebView2 窗口上不稳定，曾导致窗口几何损坏与桌面黑屏；采样只读、可控、可降级 |
| 明文保存密钥 | 系统凭据库 | v0.1 减少平台依赖；文件权限由用户目录保护，文档明确告知 |

## 6. 已知限制与后续

**v0.1 限制**

- 仅打包 Windows（NSIS，当前用户安装）；macOS/Linux 未验证；
- 无翻译历史；关闭窗口即丢弃本次内容；
- 单次文本上限 5000 字符，超出提示分段；
- 位置基于鼠标所在显示器的工作区，未处理任务栏在顶部/侧边的特殊布局；
- 窗口位置以物理像素保存；显示器布局大幅变化时只做可用性检查，失效则回退居中；
- 置顶状态只在标题栏图钉与托盘菜单中切换，未放入设置表单；
- 密钥明文存放；
- Windows 无法使用 iOS/macOS 原生 Liquid Glass：材质由 CSS 合成，背景是呼出时的一次性桌面缩略图，移动窗口后不会实时更新；
- 为保证稳定性，窗口不启用 DWM 毛玻璃/亚克力特效；
- 设置页高约 723 px，小屏（768 px 高）下会接近屏幕边缘；
- 未接入自动更新与代码签名。

**后续优先级**

1. 补齐韩语与长文本回归，整理错误码对照表；
2. Windows DPAPI 加密保存密钥；
3. 翻译历史（仅本地、可一键清空）；
4. 划词翻译（监听选区/快捷键取词）；
5. 自动更新与签名安装包；
6. 实时背景采样（拖动/切窗时刷新）与真正的原生折射。
